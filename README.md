# docker-docker-compose.doc


# Контейнеризация программного обеспечения: технология Docker как современный инструмент разработчика

# ВВЕДЕНИЕ
Актуальность темы:

Современный мир невозможно представить без компьютерных программ и сервисов. Однако разработка ПО - это не только написание кода, но и его запуск на разных компьютерах. Главная проблема, с которой сталкиваются программисты: программа отлично работает на компьютере создателя, но выдаёт ошибки при запуске у пользователя или проверяющего. Это происходит из-за различий в операционных системах, версиях программ и настройках.

Технология контейнеризации (и в частности программа Docker) стала стандартом в IT-индустрии, так как она позволяет упаковать программу вместе со всеми её настройками в один защищенный «контейнер», который гарантированно запустится на абсолютно любом компьютере.

Цель проекта:

Изучить принципы работы технологии контейнеризации Docker и продемонстрировать её преимущество как ключевого инструмента в работе современного IT-специалиста.

Задачи проекта:

   1. Разносторонне изучить понятие контейнеризации и историю её возникновения.

   2. Сравнить технологию контейнеров с традиционными виртуальными машинами.

   3. Описать базовый инструментарий разработчика и роль Docker в нём.

   4. Создать практический пример «контейнера» с простой программой.


# ТЕОРЕТИЧЕСКАЯ ЧАСТЬ
# 1.1. Проблема «На моём компьютере всё работало!»

Когда программист создает приложение, оно зависит от десятков внешних файлов, библиотек и настроек операционной системы. Если перенести программу на другой ПК, где этих файлов нет или они другой версии, программа сломается.

Раньше эту проблему решали двумя путями:

    Писали длинные инструкции по настройке (что часто приводило к ошибкам из-за человеческого фактора).

    Использовали «виртуальные машины» — эмуляцию целого второго компьютера внутри вашего. Но этот способ требует слишком много ресурсов (памяти и мощности процессора).

# 1.2. Что такое Docker и как работают контейнеры?

Чтобы объяснить работу Docker простой аналогией, представьте морские грузовые перевозки. Раньше каждый груз (мешки, бочки, ящики) погружали на корабль вручную — это было долго и неудобно. Затем придумали стандартные металлические контейнеры. Неважно, что внутри — одежда, бананы или запчасти — контейнер имеет стандартный размер и погрузочные крепления.

Docker (Докер) — это «грузовой порт» для программного обеспечения.
Он упаковывает программу и все нужные для неё файлы в один «цифровой контейнер». Такой контейнер изолирован от внешней системы и работает одинаково хорошо и на Windows, и на macOS, и на Linux.

# ПРАКТИЧЕСКАЯ ЧАСТЬ: ИНСТРУМЕНТАРИЙ И ЗАПУСК
# 2.1. Базовый набор инструментов современного разработчика

Для создания и запуска современных программ используется следующий стандартный набор:

1. Текстовый редактор/Среда разработки(IDE): место где пишут код для программ
2. Терминал (командная строка): текстовый интерфейс для быстрого управления компьютером и командами без использования мыши.
3. Вспомогательные программы для взаимодействия с командной строкой

Базовый набор утилит(программ) для удобного взаимодействия с командной строкой:
git - система контроля версий и импорта программ из основного репозитория(просто папки)
cd - перемещение по папкам (каталогам) системы.
ls - просмотр списка файлов и папок в текущей директории.
mkdir/ rm - создание и удаление папок или файлов.
cat - быстрое чтение содержимого текстового файла или конфига.


2.2. Реализация : Развёртывание файлового хранилища FileBrowser

Для демонстрации работы технологии контейнеризации из публичного реестра Docker Hub был развёрнут изолированный веб-сервис для управления файлами File Browser.

1. Запуск контейнера командой в терминале:
```Bash
docker run -d -p 8080:80 filebrowser/filebrowser

```

2. Разбор параметров:

    docker run — команда создания и запуска контейнера.

    -d (detached mode) — запуск процесса в фоновом режиме.

    -p 8080:80 — связывание порта 8080 локального компьютера с портом 80 внутри контейнера.

    filebrowser/filebrowser — имя готового образа приложения на Docker Hub.
